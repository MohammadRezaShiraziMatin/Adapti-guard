## D1 — J1 glm-4.7 `judge_parse_error` (239/488; 68/244 pairs complete; llama A0 34 vs B3 41 parse)

**Root cause**

1. **Parser is strict JSON-only** (`llm_judge._parse_judge_json`: strip fences → `json.loads`; any prose/thinking → `judge_parse_error`). GLM-4.7 frequently returns non-JSON or JSON wrapped in reasoning/markdown (OpenRouter reasoning models).
2. **No raw judge text in pack** → cannot post-hoc classify failure modes; log shows only aggregate counts.
3. **Arm differential (llama 34 vs 41)** is consistent with **stochastic judge output** plus **B3 changing target transcript** (different `model_response` / turn history in judge payload via `build_b2_judge_input` task_context). B3 does not increase parse rate uniformly (qwen B3 parse 28 < A0 36); llama is the outlier arm pair.

**Code refs:** `src/adapti_guard/evaluation/llm_judge.py` (parse), `configs/models_q1_eval_panel.yaml` (`q1_judge_glm_4_7`, max_tokens 512, no `reasoning` / `response_format` pin).

**Minimal fix**

- Harden parsing: extract first `{...}` object / JSON repair before fail.
- Panel: `response_format: json_object` or OpenRouter `include_reasoning: false` / `reasoning: { enabled: false }` for J1 (and probe on 8 calls).
- Optional: raise judge `max_tokens` or split reasoning budget so `content` holds JSON.

**Tests:** unit tests on `_parse_judge_json` with fenced/prose/reasoning-prefixed samples.

## D2 — ASR denominator includes judge-fail episodes

**Root cause:** `_post_run_analysis` computes `asr_j1 = successes / n` over **all** arm rows. `compute_real_metrics` in `attack_success.py` already **excludes** judge-fail episodes (`episode_judge_failed`), but the P1 pack summary path does not.

**Evidence (llama B3):** raw ASR 6.56% (4/61) vs judgeable-only ASR 20% (4/20).

**Minimal fix:** In `_post_run_analysis`, denominator = episodes with `not q1_episode_judge_failed(_row_as_eval(r))`; report `n_judgeable` alongside ASR.

**Tests:** regression on synthetic rows mixing parse_error and successes.

## D3 — J2 wiring and κ = 1.0

**Findings**

- **`j2_model=None` on 390 rows:** expected — only `j2_required` rows set `j2_model` (98/98 non-null). Not a wiring bug.

- **κ = 1.0 with 58 J1 parse errors:** both J1 and J2 map parse/API failure to `attack_success=False` and `reason=judge_parse_error`, so labels agree on **failure sentinel**, not substantive agreement. **κ as reported is invalid for scientific J1–J2 agreement** (should exclude judge-fail on either side and require parseable JSON verdicts).

**Minimal fix:** Compute κ only on subset where J1 and J2 are judgeable; store `j2_judge_reason` / `j2_parse_error` in episode records for audit.

**Tests:** κ helper returns `nan` or skips when all rows are parse failures.

## D4 — B3 `blocked=0` on all 244 B3 episodes

**Root cause (by design in current wiring, not “B3 inactive”)**

1. P1 uses **pre-target** path: `AdaptiveEpisodeRunner._run_b1_pre_target` + `baseline_defense_fn=bundle.defense_fn` (`q1_p1_live_runner.py`).
2. `AdaptiveDefenseState.evaluate` returns `(action, blocked, content)` where `blocked = not defense.allowed` (mainly **A3 hard block**). B3 typically applies **A1/A2 containment** with `blocked=False` and still calls the target.
3. Episode **`blocked` field** in pack comes from `synthesize_b2_eval_episode`, which sets `blocked=False` whenever any turn reached the target (not from defense telemetry).
4. **Detector/contain/block counts** live in `AdaptiveDefenseState._last_outcome` (`detector_hit`, `blocked`, `contained`, `action`) but are **never serialized** to `episodes.jsonl`.

**Conclusion:** B3 pre-target defense **ran**, but **block bit is the wrong observability** for B3; intervention is mostly non-blocking containment.

**Minimal fix:** After each episode, snapshot `bundle.state._last_outcome` (and per-turn actions if needed) into episode JSON for B3/A0 arms.

**Tests:** offline unit test that mock defense state produces telemetry fields in record builder.

## D5 — Qwen3 empty target outputs (9)

**Root cause (hypothesis strongly supported by code + catalog)**

- OpenRouter client uses only `message.content` (`OpenRouterTargetModel.generate`, line ~157).
- Qwen3 on OpenRouter lists `reasoning`, `include_reasoning` in catalog (`configs/mt2_openrouter_catalog_snapshot.json`); reasoning tokens can consume `max_tokens=512`, leaving **empty `content`** → judge sees empty `model_response` → reasons like “Empty response…”.
- Not verified token-by-token offline (no raw target payloads in pack).

**Minimal fix:** For Qwen primary targets: disable reasoning via OpenRouter extra body; and/or merge `reasoning` into visible text when `content` empty; optionally increase `max_tokens`.

**Tests:** mock OpenRouter response with empty content + reasoning field → adapter returns non-empty text.

## D6 — No raw target/judge text in pack
