## Cross-cutting findings from re-checking (they drive several grades)
- **X1. The "confirmatory subset" is itself post hoc.** The preregistration (docs/DESIGN_VARIANCE_STUDY.PREREG_2026-10-15_2240.md L166–172; hash 97bdb074… verified byte-exact) never mentions excluding AgentDyn shopping/github. The exclusion was chosen *after* the full-data results existed. Timeline: rankflip/results.json 2026-10-15 22:59; the GT audit that motivated the exclusion is 2026-10-16 00:29; review/run.py comes later still. The confirmatory and full flip sets are not nested: gemini-2.5-pro drift vs piguard flips only in the subset. So "CONFIRMATORY" really means "preregistered rule applied to a post-hoc data subset". That is DEV-affected and should be labelled that way.
- **X2. The preregistered PRIMARY statistic is Kendall τb with a bootstrap CI (prereg L170). Flip counting is the decision rule.** The manuscript makes the flip count the headline and reports τb as point values only. The re-run shows the τb CIs (e.g. llama 0.551 [0.31, 0.71]; AgentDojo 0.8 [0.8, 1.0]), but there is no τb-based inference in the paper.
- **X3. Prereg not blind to the mechanism.** Before the prereg was written (22:40), the same analyst had already seen the judge pilot (21:24) and labelled 53 + 60 gpt-4o episodes in which tool_filter/PG2 attempts did not execute. So the attempted-vs-executed hypothesis came from inspected data. That is legitimate but should be disclosed. The text "BEFORE any new run data/traces were scored" is literally true but incomplete.
- **X4. AgentDojo contributes 1 eligible cell (gpt-4o-2024-05-13, 5 defenses, no progent/drift) with 0 flips.** Every flip, in every analysis, is on AgentDyn. In the confirmatory subset, AgentDyn means **dailylife only** (20 user tasks × 10 injection tasks, 2 of which are defective).
- **X5. Fragility.** Dropping progent gives 1/9 cells. Dropping drift, piguard_detector or tool_filter gives 2/9. All of these fall below the 25% threshold (lodo_results.json; re-run). The threshold is met by exactly one cell of margin (3/9 vs the required ≥2.25).
- **X6. Shaw already separates blocked vs never-attempted calls in the harness** (2609.32691 p.4 right column: "A blocked call is recorded… stopped is distinguishable from one the agent never attempted"). The manuscript's "Shaw does not contrast attempted with state-executed success" is true for metrics/rankings but understates the conceptual overlap.
- **X7. dailylife inj2 counted as a "defect" with an unverified root cause.** The released runs show security()=True for 162/1460 inj2 episodes (rankflip/episodes.jsonl), so the checker can fire. The failure may be an artefact of the audit harness (gt_audit.py), not a benchmark defect. `TaskSuite.check()` was not actually executed; its failure is inferred from reading the code (GT_AUDIT.md).
